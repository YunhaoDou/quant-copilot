# Quant Copilot 剩余性能优化待办

更新时间：2026-11-14

## 优化边界

所有优化必须保持完整股票与ETF范围、数据口径、策略规则、历史账本和学习进度。不能通过减少扫描对象、降低核验标准、延长行情有效期或填充估算数据提高表面速度。

本轮实现已收口；逐项证明与仍存在的限制见 [最终验收记录](performance-final.md)。独立IOPV备用源按用户选择保留未授权，不计为已接入。

## P0：优先处理

- [x] **建立固定性能基准**
  - 统一冷启动、热缓存、后台扫描中的测试条件。
  - 记录接口P50/P95、CPU、内存、响应体积和请求量。
  - 验收：能够在相同条件下复跑，并同时比较性能与数据一致性。
  - 第三轮：已提供固定请求、12轮样本、并发4、代码指纹与资源采样；已采集启动后和热缓存样本。后台扫描场景仅在确认有扫描任务时允许执行，最终轮已采集后台扫描场景，96次请求均成功；慢请求详见最终记录。

- [x] **缩短后台重启等待**
  - 当前部署重启存在不可访问窗口。
  - 启动流程等待健康检查通过后再开放页面，并明确显示恢复状态。
  - 验收：测量重启到可用的时间，验证恢复后账本完整、无重复成交。
  - 第三轮：真正就绪检查、断连提示和受保护的重启入口已完成；回测依赖按需加载后，本机最后一次重启约14.964秒，8份账本核验通过、无新增成交。非零停机时间仍存在。

- [x] **完善数据源故障处理**
  - 东方财富ETF折溢价接口出现过断开连接。
  - 补充有限重试、错误分级与可核实的备用源。
  - 验收：缺失继续显示未知；备用数据明确标注来源、时间及口径，不使用估算值冒充真实报价。
  - 第三轮部分完成：最多两个同供应商节点、限流停止、错误分类、7秒分析等待上限、来源与时间显示，失败时保留净值指标。独立备用方案已核实授权范围并在界面明确显示未授权；用户选择暂不授权，因此不启用、不以估算填补。此项仅完成容错及授权状态展示。

## P1：减少主要读取与调度开销

- [x] **继续压缩策略页面加载量**
  - 第四轮：策略总览脚本由822,078字节降至413,187字节；独立策略按打开时加载，遗留净值图仅选中账户后加载。
  - 按实际展示需要加载，保留所有查看入口。
  - 验收：脚本体积下降，八个策略及遗留只读功能完整可用。

- [x] **补齐页面轮询管理**
  - 第四轮：市场雷达、情绪周期改用共享读取层；隐藏暂停、可见恢复、连续失败有界退避、旧请求取消与回放单次读取已验证。
  - 统一隐藏暂停、恢复刷新、取消请求和错误退避。
  - 验收：页面不重叠请求，隐藏后暂停读取，恢复后刷新；后台策略独立持续运行。

- [x] **优化完整证券名单读取**
  - 第四轮：新增`/tickers/search`，行情选择器首次读取约6KB；原`/tickers`完整数组契约仍保留。
  - 新增轻量搜索接口供界面使用，同时保留完整接口与全市场搜索能力。
  - 验收：所有证券均可查询，代码、名称、资产类别及原接口契约保持一致。

- [x] **防止大响应重复编码**
  - 同一缓存未命中时，并发请求仍可能重复编码和压缩。
  - 加入同键请求合并。
  - 验收：同键并发只生成一次响应，结果、ETag及错误处理保持正确。

- [x] **完善后台任务资源分配**
  - 先测量全市场扫描是否挤占持仓报价、交互查询和策略撮合资源。
  - 根据测量设置并发预算与优先级。
  - 验收：完整扫描覆盖不变；持仓与交互响应改善，策略执行不遗漏、不重复。

- [x] **审查数据库连接生命周期**
  - 检查其余SQLite连接是否及时关闭，以及长事务、写锁和WAL增长。
  - 验收：连接与文件句柄稳定，异常时正确回滚，历史数据和事务原子性保留。

## P2：精细优化与运维完善

- [x] **建立缓存内存预算**
  - 测量多版完整快照的实际内存占用，按容量淘汰缓存。
  - 验收：缓存占用受控；证券、账本和持久化历史不删减，过期版本处理明确。

- [x] **优化图表交互**
  - 测量K线悬停、区间切换及长曲线渲染，再减少重复计算。
  - 验收：交互响应改善；价格、成交量、均线、日期及复权口径逐项一致。

- [x] **完善更新与回退**
  - 当前支持手动回退旧构建。
  - 增加新版本启动失败后的自动恢复，并检查多次启动是否产生重复进程。
  - 验收：启动失败可恢复旧版本，多次启动不重复运行服务，账户状态不受影响。

- [x] **固化自动验收**
  - 将数据一致性、账本保护、页面交互、性能基准和重启恢复整理为可重复执行的检查流程。
  - 验收：能够输出实际结果、失败原因和测量环境，不将外部接口失败计为通过。

## 推荐执行顺序

1. 建立固定性能基准。
2. 缩短后台重启等待。
3. 完善真实数据源故障处理。
4. 按测量结果推进P1项目。
5. 对确认存在瓶颈的图表、内存和运维环节实施P2优化。
