# 最终性能优化与验收记录

日期：2026-11-14。范围：第三、四轮及本轮未提交的性能改进。

## 已实施

- 同键响应编码合并，并发只编码一次；失败可重试。gzip拒绝及弱ETag比较均有回归用例。
- 保留缓存预算：完整文档96MiB、读取模型192MiB、编码响应32MiB、日线128MiB。超大结果完整返回但不缓存；旧版本淘汰后返回409，禁止跨版本拼接。预算并非进程RSS上限。
- 报价和日线分别总容量6、后台最多4，为交互保留容量；后台仍遍历完整母池，持仓报价优先，不改变信号、交易规则及行情有效期。
- SQLite连接明确提交或回滚后关闭。300次连接检查文件描述符由4到4；事务、异常关闭和回滚有回归测试。
- K线缓存完整历史计算，悬停仅更新指示；共享历史缓存最多64项。MA200、窗口、日期、鼠标与键盘操作有浏览器验证，数值公式保持原样。
- 前端构建成功后才切换；新服务失败自动恢复旧构建并返回失败状态，多次启动串行化。两项隔离恢复测试不触碰实际3000端口。
- 系统设置新增“运行与性能”，展示资源预算、等待、WAL和独立IOPV未授权状态。默认仍进入连接设置。
- 统一验收包含逐行数据一致性、页面交互、账户保护、类型检查与并发采样。浏览器实际网络拒绝写操作；页面内数据夹具不产生真实变更。

## 性能实测与限制

后台扫描场景96次请求全部成功，唯一代码覆盖及八策略数量校验通过。该轮部分接口仍慢：策略总览P95约17.1秒，红利摘要约11.4秒，完整名单约6.8秒。运行中机器有其他应用负载，不能作为纯粹的前后提速结论。

统一验收最初为整个96请求步骤设置90秒时限，该轮超时已记录为失败；诊断确认请求成功返回，并非死锁。现总时限600秒，与每请求20秒及固定轮数匹配，仍记录每项P50/P95和错误；不以放宽总时限宣称变快。后台采样不能等同空闲热缓存场景。

独立IOPV备用源需要单独授权且候选接口仅覆盖深市；用户暂不授权，当前不启用。原来源失败继续显示未知，不能保证外部免费接口随时可用。

缓存预算和网络容量并不能消除Python大快照解码的CPU争用；慢请求仍是实际限制。此轮完成列出的实现和可复验入口，不承诺所有机器或所有扫描阶段达到固定秒数。
