# 性能优化与正确性验收

本轮优化仅改变读取、缓存、传输和调度；不改变策略门槛、模拟撮合规则、财务口径、真实行情时间或全市场覆盖范围。2026-11-13 本地验证：股票5580只、ETF1720只，8个独立模拟账户。

## 查询与数据边界

- 红利与多因子采用「轻量进度摘要 + 服务端全市场筛选 + 50只分页」。分页只控制展示数量，不限制扫描、搜索、异常记录或候选数量。每条证券返回完整原字段。
- 红利分页固定快照版本，保留最近3版；过期版本返回409并提示刷新，绝不混合版本。所有筛选、排序及汇总用扫描日同一快照；实时报价另行覆盖显示，不冒充扫描时财务或筛选结果。
- 已完成快照按实际JSON内容及配置识别变化，即使更新时间未变化也能失效。后台预热查询模型；原全量接口继续兼容已有客户端。
- 条件请求ETag/304和压缩减少重复传输，浏览器共享重复GET；输入防抖，取消已卸载页面的读取，隐藏页暂停轮询，恢复可见时刷新。后台策略不依赖浏览器可见性。
- 报价按证券复用并合并重叠请求，保留供应商报价时间及原新鲜度门槛。日线缓存保留日期、收盘边界、复权和根数维度，按容量逐步淘汰，不整库清空。

## 后台与持久化

- 板块采集、股票账户、ETF/SHIBOR、只读快照预热分别调度，慢供应商请求不再串行拖住整个周期。股票报价分批有限并发，账户轮次为单执行者。
- SQLite启用WAL，初始化检查不重复执行；已有实验读取不申请写锁。编码在写事务外完成，账本及候选仍使用原事务更新方式。
- 大型JSON编码和同步读取移出异步请求主线程。健康检查复用数据库连接池，数据库与Redis并行有界检查；另有轻量存活检查。
- 已对8份账本逐项核对建账时间、本金、规则和原成交流水前缀；未重置账户、改写历史或回填成交。

## 日常启动

原应用和start.sh自动使用生产前端，不再每次启动开发编译器。源码与公开配置的指纹不变时复用完整构建；源码变化先构建成功再切换。macOS前端由launchd托管，不随启动终端退出。开发可显式设置QUANT_FRONTEND_MODE=dev。

上一个完整构建保留，可执行 `bash scripts/frontend-service.sh --rollback` 回退前端。构建失败不会停止正在运行的前端；运行时启动失败会返回错误，旧构建保留供回退。运行状态及构建指纹记录在backend/logs/frontend-release.json；文件不纳入Git。

## 本机测量

以下是不同负载下的本机样本，不是固定性能承诺。最后一轮生产服务、连接复用，后台采集保持运行。

| 查询 | 优化前单请求 | 优化后5次样本范围 |
|---|---:|---:|
| 红利完整读取 → 同口径分页 | 9.85秒 | 13—113毫秒 |
| 多因子完整读取 → 同口径分页 | 4.74秒 | 58—122毫秒 |
| 策略完整目录 → 摘要目录 | 1.54秒 | 122—789毫秒 |
| 完整7300只证券名单 | 1.24秒 | 160—747毫秒 |

红利第一页JSON约150KB、压缩约29KB，替代每次约14MB完整传输。完整母池与全部结果仍可逐页获取；旧全量接口仍存在。

8种读取同时请求3轮时，健康检查75—280毫秒，红利分页22—382毫秒；冷缓存或后台写入密集时策略目录仍出现约2.2秒峰值。旧测试中混合请求使健康检查等待18—30秒。两次背景负载不同，不将比例当作严格实验结论。

## 保留的限制

公开行情仍存在供应商延迟、限流及缺失；优化不提高数据真实性等级，不将缺失当作0或已通过。全市场深入核验仍要实际完成完整扫描；分页快不代表扫描已完成。缓存核对周期最多1秒，实时报价原新鲜度判断不变。模拟仍不等同券商实盘，不具备盘口排队和完整成交容量模型。


## 第二轮：首屏加载与缓存争用

2026-11-13继续优化。主入口原先静态引入新手指南、研究、策略等8个面板，即使只打开驾驶舱也会下载全部模块。现全部按使用页面加载，并在地址解析完成后才挂载目标页面；内层页签也先解析深链接再挂载，避免误加载默认子页的数据。原页面、控件、课程内容、存储键和导航参数保留。

| 指标 | 第二轮之前 | 第二轮之后 |
|---|---:|---:|
| Next生产构建主入口 First Load JS | 282KB | 101KB |
| 浏览器驾驶舱首次实际JS（未压缩） | 1,003,825字节 | 409,491字节 |
| 浏览器指南首次实际JS（未压缩） | 1,003,825字节 | 476,977字节 |
| 浏览器策略目录首次实际JS（未压缩） | 1,003,825字节 | 821,567字节 |

构建指标不含进入页面后按需获取的模块，因此与浏览器总字节数含义不同。浏览器使用独立新页面，导航完成后等待1.5秒统计JS响应正文；这些样本衡量传输体积，不作为首屏耗时承诺。策略目录仍包含现有只读遗留曲线，其图表依赖按原功能加载。

缓存原先在全局锁内执行SQLite读取、JSON解析和模型构建。现按文档/模型类别独立加锁，全局锁仅保护注册表和响应LRU。隔离测试让某个模型构建持续500毫秒：无关响应等待从502毫秒降至0.057毫秒。该结果证明锁隔离效果，不代表所有真实接口均有同等比例提升。

每类最近3个快照的保留规则、旧版本409语义、同内容版本号与原值保持。新增失效代次检查，阻止显式清空后在途旧读取重新填充缓存；只读SQLite连接在读取后显式关闭。
